# 임베딩 모델 비교와 추천 (4단계 Python 쪽)

공고 글(수백 토큰)을 벡터로 바꿔 회사 소개와 비교하는 데 쓸 **한국어 문장 임베딩 모델**을, 운영 서버(Ubuntu · CPU 1개 · 여유 메모리 약 2GB · 다른 서비스와 공존 · 서비스 MemoryMax 1GB 가정)에서 CPU 로만 돌린다는 조건으로 골랐다. 외부 임베딩 API 는 쓰지 않는다.

## 결론

**`intfloat/multilingual-e5-small` 을 ONNX Runtime int8 로 돌린다**(`EMBED_BACKEND=onnx`, 기본값).

- 메모리: 최대 **약 550MB**(스레드 1개·배치 1). torch 로 돌리면 약 1.3GB 라 MemoryMax 1GB 에 들어가지 않는다.
- 속도(이 PC 1스레드): 공고 1건 약 0.13~0.18초 → **3,000건 약 6~9분**. 모델 로딩 약 1초.
- 라이선스: **MIT**. 한국어 특화 후보 `jhgan/ko-sroberta-multitask` 는 저장소에 라이선스 표기가 없다(상업 서비스에는 확인이 필요한 위험).
- e5 는 검색용(질의 `query: ` ↔ 문서 `passage: `)으로 학습돼 "회사 소개 → 공고" 구조에 맞는다.
- 차원 384(저장·pgvector 비용이 768차원의 절반).

트레이드오프: 이 작은 평가 세트에서 한국어 특화 sroberta 가 첫 정답 순위(MRR)는 더 좋았다. 다만 라이선스·표본 크기(회사 10개) 때문에 **확정이 아니라 기본값**이다. 4단계 뒤쪽(실제 공고 수백 건·정답 라벨)에서 `EMBED_MODEL`·`EMBED_ONNX_FILE` 만 바꿔 다시 비교할 수 있게 설정으로 열어 두었다.

## 후보와 받은 파일

| 후보 | 파라미터 | 받은 가중치(safetensors) | 비고 |
|---|---|---|---|
| intfloat/multilingual-e5-small | 118M(어휘 25만 토큰이 96M) | 471MB (+ ONNX int8 118MB) | MIT, 접두어 query/passage |
| intfloat/multilingual-e5-base | 278M | 1,112MB | MIT, "큰 쪽" 메모리 확인용 |
| jhgan/ko-sroberta-multitask | 111M | 442MB (+ ONNX int8 111MB) | 한국어 특화(KorNLI·KorSTS 학습), 라이선스 표기 없음, 접두어 없음 |

bge-m3(568M, 가중치 약 2.2GB)는 받지 않았다. 내려받기 약 3GB 한도와, e5-base 가 이미 "큰 쪽" 메모리 확인(최대 2.0GB)을 맡아서다 — bge-m3 는 그보다 더 크므로 메모리 결론은 같다. nlpai-lab/KoE5(2.2GB)도 같은 이유로 받지 않았다.
모델 캐시 `grantmatchpy/.models`(HF_HOME) 합계 약 2.4GB, `.gitignore` 에 있다.

## 평가 세트 (재현 가능, `tools/eval/`)

| 파일 | 내용 |
|---|---|
| `build_eval_set.py` | 개발 PostgreSQL 읽기 전용으로 공고 50건을 뽑는다(접속 값은 `GM_DST_*` 에서 읽고 어디에도 찍거나 저장하지 않는다). 무작위 없이 id 해시 순서. 30건은 (수집처 × 분야 첫 단계) 층화, 20건은 회사 소개 업종 키워드(반려·식품·농업·관광·바이오·게임·소재·핀테크·교육·금속)마다 제목에 걸리는 2건. |
| `grants_50.json` | 뽑힌 공고 50건(BIZINFO 33·KSTARTUP 17)과 임베딩 입력 글. 글 형식은 `app/embed/passage_text.py` — `[사업명] [지원대상] [분야] [지역]` 머리 줄 + 사업명·지원대상·요약·조건 문장. 비면 줄을 뺀다. 평균 259토큰(최대 499)이라 512토큰 안에 든다. |
| `companies.json` | 새로 쓴 가상 회사 소개 10개(반려동물 앱·금속가공 제조·푸드테크·바이오·AI 교육·농업 스마트팜·관광숙박·핀테크·친환경 소재·콘텐츠 게임). 이름·연락처 없음. |
| `gold.json` | **사람(작성자)이 제목·요약을 읽고 표시한 정답**(회사당 1~3건, 근거 한 줄씩). |
| `bench_embed.py` / `bench_onnx.py` | 모델·스레드·배치별 시간·메모리·벡터 측정(프로세스 하나에 설정 하나). |
| `rank_eval.py` | 상위 5개 표, recall@5, MRR. |

주의할 한계:

- 정답은 같은 사람이 같은 50건을 보고 표시했다. 회사 10개·정답 총 21건이라 **0.05~0.1 차이는 잡음 수준**이다.
- 이 DB 의 `grant_conditions` 는 전부 AI 추출(source=AI)이고 사람이 검수한 행이 아직 없다. 그래서 글에는 조건 행을 모두 넣었다(검수 상태가 생기면 `passage_text` 호출 쪽에서 걸러 넣으면 된다).
- 공고가 3,000건이 되면 후보가 훨씬 많아져 순위 점수는 내려간다. 상대 비교용이다.

## 비교표

측정 환경: Intel Core Ultra 5 125H(14스레드) · 15.6GB · Windows 11 · Python 3.14 · torch 2.14.1+cpu · onnxruntime 1.30.0. 서버는 CPU 1개라 **1스레드 줄**이 기준이다(서버 CPU 가 이 PC 보다 느리면 시간은 더 걸린다 — 아래 환산은 이 PC 기준 하한).

읽는 법:

- **메모리가 torch 로 e5-small 이 1.3GB 나 되는 이유**: torch 자체 약 200MB + 토크나이저 약 320MB(어휘 25만 토큰) + 가중치 fp32 약 470MB(그중 어휘 임베딩이 80%) + 계산 임시 공간. ONNX int8 은 torch 를 빼고 가중치를 1/4 로 줄여 약 550MB 가 된다. 토크나이저 약 250MB 는 어떤 방법으로도 못 줄인다(어휘 가지치기를 하면 줄지만 이번 범위 밖).
- **배치는 작을수록 좋다**: 패딩 낭비가 없고 메모리가 줄며, ONNX int8(동적 양자화)은 배치 안의 다른 글에 따라 활성화 눈금이 달라져 **같은 글의 벡터가 배치 구성에 따라 조금 달라진다**(코사인 0.99 안팎). 그래서 서비스 기본값을 `EMBED_BATCH=1`(지시서의 8 에서 바꿈)로 했다 — 같은 글은 언제 어떤 요청으로 보내든 같은 벡터가 나온다.
- 같은 e5-small 의 ONNX int8 벡터와 torch fp32 벡터의 코사인 유사도는 평균 0.9956(최소 0.9907), ko-sroberta 는 평균 0.9931. 순위가 같은 배치 크기에서도 잡음 수준으로 흔들리는 것이 위 MRR 차이(0.72~0.82)다.
- e5-base 는 오히려 e5-small 보다 순위가 나빴다(표본 잡음 포함). 메모리 2GB·68분(1스레드)이라 이 서버에는 맞지 않는다.
- ko-sroberta 는 코사인 값이 넓게 퍼져(관련 0.6~0.7, 무관 0.45~0.5) 점수가 보기 좋고 e5 의 압축된 값(0.84~0.89)보다 임계값을 잡기 쉽다. e5 는 순위만 쓸 때 괜찮다(순위를 쓰는 `/internal/rank` 계획에 맞다).

## 서버 값 제안 (systemd)

- `MemoryMax=1G`(여유 약 450MB) 안에 든다 — 최대 약 550MB. 동시에 두 요청이 와도 서비스가 임베딩을 한 번에 한 건씩만 계산한다.
- `EMBED_THREADS=1`, `EMBED_BATCH=1`(기본값). 다른 서비스와 같은 CPU 1개를 나눠 쓰므로 이 값이 안전하다. 호출 쪽(Java 작업자)은 한 번에 8~16건씩, 사이에 쉬면서 보내는 것이 좋다(큐 작업 설계 메모는 작업 보고 참조).
- 처음 한 번 서버에서 `HF_HOME` 을 서비스 계정 폴더로 지정해 모델을 내려받고(`python -c` 한 줄 또는 `EMBED_MODEL` 에 폴더 경로), 이후 `HF_HUB_OFFLINE=1` 로 외부 접속 없이 쓴다. 필요한 파일은 `tokenizer.json`, `onnx/model_qint8_avx512_vnni.onnx`(약 118MB)뿐이다.
- 양자화 파일 이름의 avx512_vnni 는 최적화 힌트일 뿐 AVX2 만 있는 CPU(이 PC)에서도 정상 동작하고 fp32 와 코사인 0.995 로 일치했다. 서버 CPU 에서 처음 한 번 `tools/eval/bench_onnx.py` 로 같은 확인을 하면 안심할 수 있다.
- torch fp32 로 돌리려면 서버 메모리 여유 약 1.5GB(MemoryMax 1.5G 이상)와 `requirements-eval.txt` 설치가 필요하다. 메모리가 문제없고 순위 품질이 더 필요하면 (torch · fp32 e5-small → MRR 0.82) 선택지다.

## 다시 재는 법

```powershell

.venv\Scripts\python.exe -m pip install -r requirements-eval.txt --extra-index-url https://download.pytorch.org/whl/cpu

```
